# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this project is

**Docstar Publisher** is an open-source (MIT) template for publishing documentation. Users write Markdown in `docs/` and `blog/` and OpenAPI YAML in `api-hub/`, preview them live locally, and push to GitHub, where a GitHub Actions workflow builds a static site with [VitePress](https://vitepress.dev) and deploys it to GitHub Pages.

It is meant to be forked / used as a template. Keep it simple, dependency-light, and free of project-specific content.

## Layout

```
index.md                  Home page (hero)
docs/                     type: docs  — Markdown pages (+ layout.json)
blog/                     type: blog  — posts with frontmatter (+ layout.json)
api-hub/                  type: api   — OpenAPI .yml/.yaml files (+ layout.json)
public/                   Static assets (served from site root)
  .vitepress/config.mts   Site config (title, nav, search, base path)
  .vitepress/sidebar.mts  Auto-generates sidebar + nav from docs/ folder tree
  .vitepress/layout.mts   Reads per-folder layout.json (type: docs | blog | api)
  .vitepress/generate.mts Generates API pages (from OpenAPI YAML) and blog index/tags/RSS
  .vitepress/theme/       Default theme + post date/author/tags header
.github/workflows/deploy.yml   Build + deploy to GitHub Pages
```

## Commands

- `npm install` — install deps
- `npm run dev` — live preview with hot reload
- `npm run build` — production build to .vitepress/dist
- `npm run preview` — serve the production build locally

## Conventions

- Adding a doc = adding a `.md` file under `docs/`; adding an API = adding an OpenAPI `.yml` under `api-hub/`; adding a post = adding a `.md` under `blog/`. **Do not** hand-edit the sidebar; it is generated from the folder tree. Page title = frontmatter `title:` or first `# H1`.
- One H1 per page. Use `-` bullets, fenced code blocks with a language.
- A folder's `layout.json` sets its `type` (`docs`, `blog`, `api`); see `docs/guide/writing-docs.md`. An OpenAPI `.yml` in an `api` folder is rendered automatically. Generated files (`_api/`, blog `index.md`/`tags/` marked `<!-- generated by docstar -->`) must not be hand-edited.
- Link between pages with absolute-from-docs paths without extension: `/guide/deploying`.
- Static images go in `public/`.
- The deploy base path comes from env `DOCS_BASE` (workflow sets `/<repo-name>/`); never hard-code a base path in Markdown links or config.
- Never commit `node_modules/` or `.vitepress/dist/` or `.vitepress/cache/`.
- Verify changes with `npm run build` before finishing; broken internal links fail the build.

## Deploying

Push to `main`. One-time: repo **Settings → Pages → Source: GitHub Actions**. Do not push, tag, or change repo settings unless the user asks.

## Don'ts

- Don't add heavy frameworks or a custom renderer; VitePress is the engine.
- Don't add secrets, analytics, or tracking.
- Don't change the license.
